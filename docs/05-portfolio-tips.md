# Step 5: Present it in your portfolio

## What to publish

1. This GitHub repo (see [Step 1](01-publish-on-github.md)).
2. A **view-only** link to your Google Sheets workbook: **Share > General access > Anyone with the link > Viewer**.
3. A short write-up (a Google Doc or a `docs/case-study.md`) of one page covering:
   - **The situation:** a busy consultant with a disorganized inbox.
   - **What you did:** the label system, priority rules and trackers.
   - **Problems you found:** list 5 to 8 (conflicting prices, duplicate tasks, a phishing email, a schedule clash).
   - **The result:** what Sarah would see on Monday morning.
4. Screenshots of the label structure, the Email Action List and the Dashboard, saved in `docs/screenshots/`.

## Add it to your profile

- **LinkedIn:** Profile > **Add profile section > Recommended > Add featured**, then add the repo link and the case study.
- **Resume:** one line, e.g. "Built a 30-email inbox triage system with a Gmail label structure and 7 trackers (client, invoice, task,
  follow-up, priority list and dashboard) in Google Sheets."
- Be clear that the project uses **fictional** data and is a practice exercise. Honesty keeps it credible.

## Suggested README wording for your fork

> I completed this practice project to demonstrate inbox management, invoice tracking and calendar coordination as a
> Virtual Assistant. All data is fictional.

## Quality bar for recruiters

- Spelling and consistent naming everywhere
- Clean, filtered, frozen-header sheets
- No real personal data
- Screenshots that are readable
